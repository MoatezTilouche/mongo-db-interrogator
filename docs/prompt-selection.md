The relevance computation is deterministic and performs no I/O. The boundary supplies in-memory profile snapshots and existing date-resolver constraints. Schema, rule and fact consumers share that ranked result within each prompt build. The retrieval stage calls the same computation before its rule gate. Rules cannot manufacture their initial relevance solely by referencing an otherwise unrelated field. Existing context-selection and similarity signals support disjoint question/rule vocabularies without adding embedding requests.

Field paths and type lists are copied unchanged. Signals precede structural defaults; presence sorts scalar defaults. Insufficient signals trigger the same structural fill and a diagnostic. Private/excluded ancestors also protect descendants. Named private fields can appear in a pruned schema if allowed, while facts always omit private/excluded observations. Parent paths consume the field budget and must be eligible themselves. If ancestors cannot fit a tiny budget, the relevant leaf takes precedence.

Rule drops log IDs and reasons without rule text. The cap uses the existing type order followed by signal count. The collection gate uses kept rule scopes/source metadata, question field/value signals and already published descriptions/aliases. Relationship-only endpoints cannot support an unrelated collection: both collections need independent support. It preserves at least one collection. Logging mode records prospective drops and leaves the original selection intact.

Practical limits and decisions where requirements intersect:

- Schema passthrough for small/unprofiled collections follows the explicit compatibility rule; those schemas do not gain new privacy filtering. Facts still apply their safety filter.
- Mixed-profile rule sets preserve legacy handling for rules scoped to unprofiled collections. Their presence can exceed the new four-rule budget; existing caps remain in force. Existing supplement applicability filters, conflict handling and the per-field coded-rule cap remain in place and can further reduce rules that pass the new gate.
- A safe nested/container path is a final structural fallback if a profile has no scalar defaults. When no eligible profiled path exists at all, the collection metadata and omitted-fields note remain with an empty field map. This avoids exposing excluded paths or aborting query generation; it is the exception to nonempty field fallback. Full validation remains unchanged.
- Field/value/date signals compete within hard budgets. More required paths or relevant date/value fields than the configured cap cannot all be shown. Deterministic ranking chooses the visible subset, and full validators still accept omitted valid fields. Existing character limits can further shorten facts.
- Similarity uses available compatible vectors/scores only. Missing vectors do not trigger embedding calls; structural defaults and existing context selections provide the fallback. This is not a measurement of live model accuracy.
- The context-selection agent's own prompt, template parameter-extractor prompt, stored schemas/profiles and template persistence are outside this prompt-data change. Previous query JSON and user preferences remain intact. No live database/cache availability or service credentials were tested.

All changes remain uncommitted. No dependencies were added and no commit, staging, branch or push operations were performed.
